# Design: Bonereaper-style tactic + offline replay backtest

**Date**: 2026-05-28
**Status**: approved (design), pending implementation plan

## Problem

Paper-режим, phase-13: бот зробив −$247.51 на 16 ринках (win rate 31%) за 27 хв,
потім kill-switch зупинив його на −$110. Навіть з фейковими 100%-fills бот у
мінусі → проблема в **тактиці**, не в бюджеті/fill-rate.

Конкурент [@bonereaper](https://polymarket.com/@bonereaper)
(`0xeebde7a0e019a63e6b476eb425505b7b3e6eba30`) на тих самих 16 вікнах: +$138.83
(оцінка), +$14 118/добу загалом, 45 189 угод.

## Root cause (доведено на даних)

Розклад мого PnL по 16 ринках:

| За часом входу | PnL | | За ціною входу | PnL |
|---|---|---|---|---|
| рано (<33%) | −$38.13 | | дешево (<0.40) | −$18.23 |
| середина (33–66%) | −$1.06 | | середина (0.40–0.60) | −$66.94 |
| **пізно (>66%)** | **−$208.32** | | **дорого (>0.60)** | **−$162.34** |

Профіль входу Bonereaper vs мій (ті самі 16 ринків):

| | Сер. ціна (переможець) | Сер. ціна (програш) | Сер. час входу | win/lose shares |
|---|---|---|---|---|
| Bonereaper | 0.519 (med 0.50) | 0.390 | 43–49% | 1.19 |
| Мій бот | 0.622 (med 0.64) | 0.508 | 64–67% | 0.64 |

**Механізм**: мій бот — пасивний two-sided maker, що бідає нижче mid. Рано
ніхто не зливає (напрямок неясний) → bid'и не filled. Пізно, коли напрямок
ясний, на bid'и зливають **програшну** сторону (adverse selection), а бот ще й
доганяє фаворита по 0.6–0.9. У 5m-crypto ціна постійно whipsaw'иться (приклад:
BTC-5m YES впав до 0.235 → стрибнув до 0.995), тож купівля фаворита по 0.9
регулярно стає 0.

Bonereaper заходить **рано (43–49%) близько справедливої ціни (~0.5)**, бере
аутсайдера дешево (0.39), має більше переможних шар, ніж програшних.

`directional_filter` (phase-13) і `directional_size_skew` **посилюють** проблему
— скеровують капітал саме на дорогу сторону-фаворита.

## Goals

1. Переписати тактику входу на Bonereaper-style: **ранній вхід + cap ціни**,
   прибрати chase-the-favorite.
2. Збудувати **офлайн replay-бектест** для чесного детермінованого A/B
   старої vs нової тактики на реальних історичних цінах.

Non-goals: live-торгівля, зміна risk-модуля, оптимізація latency/executor.

## Component 1 — Backtest harness (`quoter/backtest/`)

Окремий офлайн-модуль, не торкається live-боту.

- **`fetch.py`** — тягне з Polymarket resolved BTC/ETH up-down ринки (5m/15m):
  список + по кожному траєкторію ціни через CLOB
  `prices-history?market=<tokenId>&startTs&endTs&fidelity`. Кеш у
  `quoter/backtest/data/*.json` (не довбати API повторно). Стартова вибірка: 16
  наявних у `state.db` + добір через markets API до ≥50 (ціль ~100+).
- **`fillsim.py`** — детермінована fill-модель під грубу історію (~1 точка/хв).
  Правило: resting bid сторони S за ціною P вважається filled на інтервалі,
  якщо ціна S падає ≤ P (контрагент зливає тобі). Розмір fill — частка бюджету
  квоти. Свідомо спрощено; **ідентично** для обох конфігів → A/B чесне.
- **`engine.py`** — на кожному кроці траєкторії викликає реальний
  `compute_ladder(cfg, mid_yes, time_to_expiry, …)`, проганяє квоти через
  fillsim, акумулює позицію; на резолюції рахує PnL = winshares·$1 − total_cost.
- **`run_backtest.py`** — проганяє ≥1 конфіг на всіх ринках, друкує таблицю:
  PnL, win-rate, avg entry price (win/lose side), avg entry time, worst market.

**Інваріант**: engine викликає справжній `compute_ladder`, тож бектест тестує
бойовий код стратегії, а не його копію.

**Обмеження**: історія груба (~1 точка/хв, ~5 точок на 5m-вікно) — захоплює
форму траєкторії, не мікроструктуру. Достатньо для A/B «рано vs пізно» і
«cap ціни», недостатньо для оцінки реального fill-rate.

## Component 2 — Tactic changes (`ladder.py` + `config.py`)

Усі пороги — параметри конфігу (тюняться бектестом, не вгадуються):

1. **Late-stop** — новий `entry_cutoff_frac` (старт 0.50). Якщо
   `window_frac > entry_cutoff_frac` → `compute_ladder` повертає `[]` (тільки
   тримати/merge, без нового набору). Ціль: −$208 пізніх філсів.
2. **Price-cap** — новий `max_entry_price` (старт 0.60). У `_layer_a_continuous`
   і `_layer_b_cheap_tail` відкидати квоти з `price > max_entry_price`. Ціль:
   −$162 дорогих філсів; купуємо лише дешеву/справедливу сторону.
3. **Вимкнути chase-the-favorite** — `directional_filter_enabled=False`,
   `directional_size_skew_enabled=False` за замовчуванням (дані: посилюють
   програшну сторону).
4. **Рання агресія для реальних філсів** (LIVE-AFFECTING, перевіряти обережно):
   у першій чверті вікна дозволити топ-рівень бідати at mid (offset 0), щоб
   filled рано як Bonereaper. У paper/бектесті fill-модель і так filled, тож
   ефект перевіряється лише live → позначено окремо, не блокує бектест.

## Component 3 — Tuning process + success criteria

1. Baseline: проганяю поточний (phase-13) конфіг через бектест → опорний PnL.
2. Sweep сітки `entry_cutoff_frac` × `max_entry_price` → таблиця PnL.
3. Вибір конфігу: максимум PnL **і** менш від'ємно-асиметричний розподіл
   (враховувати worst-market, не лише суму).
4. **Критерій успіху**: новий конфіг б'є baseline по сумарному PnL і по
   worst-case на вибірці ≥50 ринків (анти-оверфіт на 16).
5. ⚠️ Застереження: бектест груби + симульовані філси. Структурну перевагу він
   показує; реальний fill-rate — лише live-тест із малим капіталом.

## Risks

- **Оверфіт на малу вибірку** → вимога ≥50 ринків, дивитись на розподіл.
- **Груба історія** ховає whipsaw всередині хвилини → fill-модель консервативна,
  однакова для A/B.
- **Paper ≠ live fill-rate** → явне застереження, фінал лише live.
- **Рання агресія (at-mid bid)** змінює live-поведінку → окремий прапорець,
  не вмикати без live-перевірки.
